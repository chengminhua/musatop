# 验证记录（v0.1.0 至 v0.2.0）

验证日期：2026-10-08。以下为实际执行结果，机器地址、账号、UUID 和业务命令均未纳入仓库。

## 环境

| 项目 | 实测值 |
| --- | --- |
| 开发环境 | Linux aarch64，Python 3.12.3 |
| 验证服务器 | Ubuntu 22.04.4，x86_64，Python 3.10.12 |
| GPU | 8 × X10000，GMI 每卡报告 81920 MiB（80 GiB） |
| 驱动 / GMI / MTML | 3.3.8-server / 2.3.3 / 2.3.5-linux |
| 主机 MUSA Toolkit 元数据 | 4.3.2 |
| 测试程序编译器 | 机器已有开发镜像中的 mcc 4.3.5，目标 mp_31 |
| psutil | 7.2.2 |

主机 SDK 缺少 `musa_runtime.h` 等运行时头文件。测试程序使用已有镜像中的完整 SDK，在无网络、无 GPU 的临时编译容器中构建；可执行文件随后在宿主机运行。没有修改系统 SDK、驱动或 Python。监控工具本身不需要 SDK。

MUSA Runtime 查询报告设备名 `MTT S5000`、计算能力 3.1、warp size 32；同一设备的 GMI 产品名为 `X10000`，musatop 按 GMI 显示型号。其他服务器或型号尚未验证。

## 自动化测试

Python 3.10 与 3.12 均通过 88 项 unittest，包含：

- GMI JSON 与进程表解析、真实脱敏进程样例、缺失值、单位、空设备/空进程、异常结构、命令失败及超时。
- 设备 UUID/索引一致性、部分失败时保留旧数据与时间、恢复后清除过期状态。
- 进程退出、权限不足、PID 重用、单 PID 多卡采样复用、CPU 首次未知。
- SIGTERM 身份校验、pidfd 与回退路径，以及自建真实子进程的终止和回收。
- CLI 参数、筛选排序、JSON/文本输出、错误退出码与终端控制字符处理。
- 真实伪终端按键、缩放、正常退出与异常退出后的终端恢复。

命令：`python -m unittest discover -s tests -v`。这些测试不启动 GPU 工作负载。CI 配置覆盖 Python 3.10/3.12；本记录中的结果来自本地与验证服务器，云端 CI 结果以 GitHub Actions 为准。

## 真机负载与交互

运行前检查八卡显存、利用率为零且无 GPU 进程，仅对自建测试程序操作。

| 场景 | 结果 |
| --- | --- |
| 空闲八卡 | 编号 0–7、型号、80 GiB 容量、版本及各项指标正常采集 |
| 单卡 20 秒小负载 | 测试 PID 被发现，GMI 与 musatop 的 PID/卡号/进程显存一致，正常结束后显存释放 |
| 同一进程使用八卡 | 八张卡的进程归属正确；每卡进程显存 111 MiB（116391936 字节） |
| 动态指标 | 在有限占空比负载下观测到 GPU 利用率峰值 24% |
| 八卡 SIGTERM | 仅终止自建进程，程序清理退出码 143，八卡显存释放，进程从 GMI 消失 |
| 真机 80×24 TUI | 显示测试 PID、帮助和完整详情；`k → n` 后仍存活；`k → y` 实际终止并释放显存 |
| 终端恢复 | 真机 TUI `q` 退出码 0，退出前后 termios 属性完全一致 |

负载每卡显式分配 64 MiB，额外运行时开销计入实测的 111 MiB 进程显存；设备总显存增加也确认低于每卡 1 GiB。测试不测性能上限。显存容量、PID 和进程显存做一致性比较；温度、功率和利用率在两次查询间可能自然变化，不要求逐个瞬时数值相等。

`tests/fixtures/gmi_x10000_process.txt` 保留真实进程表格式，但 PID 和路径已经替换；其他 fixture 用于构造多卡、缺失字段等边界情况。

## 十分钟持续采样

后台采样器实际运行 600.07 秒，获取 600 个快照：

- 采集错误与过期快照：0。
- 最大观察间隔：1.203 秒。
- Python 监控进程 RSS：16310272–17539072 字节（约 15.55–16.73 MiB）。
- Python 监控进程平均 CPU：单核的 0.44%；该值不包含 GMI 子进程 CPU。

持续采样期间包含前述小负载与进程退出场景。检查八卡数量和显存容量保持正确；这是一轮十分钟稳定性验证，不代表无限时长运行保证。源代码审查后的解析边界修复另外通过完整测试、真机采样和 TUI 验证。

## 构建与范围

交付格式为 Python wheel 与源码包，命令入口 `musatop` 和 `python -m musatop`。离线依赖装在独立虚拟环境中。构建产物、原始采样和环境均不提交 Git。

已验证 Linux 宿主机物理 GPU；容器内运行、MPC/vGPU、其他型号/驱动版本不在此次验证范围。未将工具用于控制任何已有业务进程，也未修改 GPU 配置。

## v0.1.1 回归（2026-10-08）

针对另一台八卡 X10000 宿主机上的 Toolkit 与功率上限 N/A，完成以下验证；本轮仅监控，不新增 GPU 工作负载。

- Python 3.12.3（本地）与 3.10.12（服务器）均通过 **114 项 unittest**。新增覆盖安装路径选择/冲突/软链接/坏元数据、上限未知/零值/别名优先级及诊断展示。
- wheel 与 sdist 构建成功；wheel 在服务器独立干净虚拟环境中离线安装成功，入口报告 `musatop 0.1.1`。
- 驱动 3.3.7-server / GMI 2.3.3：正确识别八卡、每卡 80 GiB，Toolkit 从 `/usr/local/musa-4.3.2/version.json` 读取为 `4.3.2`；采集错误为零。实时功耗可读，上限均为 `null` 且说明 GMI 未报告。
- 驱动 3.3.8-server 的对照节点：八卡上限仍为 `950 W`，`power_limit_reason` 均为 `null`，Toolkit 仍为 `4.3.2`，采集错误为零。
- 服务器实际 GMI + 80×24 伪终端：Toolkit、缺失原因、帮助均可见，`q` 退出码为 0，前后终端 termios 属性完全一致。
- 独立代码审查与文档证据边界复核通过；具体诊断、驱动差异和未验证部分见 [N/A 定位记录](NA_DIAGNOSIS.md)。本轮没有重复初版的十分钟负载验收，也没有执行驱动升级。

## v0.2.0 进度条与五分钟趋势（2026-10-08）

本轮在同一八卡 X10000 验证节点的独立源码目录和虚拟环境中进行，未替换旧部署、修改驱动或控制业务任务。驱动 3.3.8-server、GMI 2.3.3、MUSA Toolkit 4.3.2、Python 3.10.12、psutil 7.2.2。

### 自动化与终端

- Python 3.12（本地）与 3.10（服务器）均通过 **170 项 unittest**。覆盖 Unicode／ASCII 部分填充、无色回退、未知与过期状态、300 秒淘汰、峰值合并、不同采样间隔、故障恢复、设备身份和容器副本隔离。
- 80×24 模拟终端精确验证八张卡、五行进程和三行趋势；容量／窗口宽度的 24 组边界检查确保显存单位变化不挤掉功率上限、百分比列不跳动。独立审查发现的该截断问题已修复。
- 实际 GMI + 真实伪终端分别通过默认彩色 Unicode、`--ascii`、`--no-color` 三种模式；执行趋势切卡／开关、刷新、帮助及 80／40／60／100 列缩放。退出码均为 0，termios 属性完全恢复。
- wheel 与 sdist 构建成功；wheel 在服务器另建的干净虚拟环境中离线安装通过，命令入口报告 `musatop 0.2.0`。
- 独立审查通过；文本／JSON 输出兼容性和 `schema_version=1` 保持不变。历史只保存在运行内存，不增加 GMI 查询。

### 有限负载

每轮启动前重新检查 GPU 空闲、无 GPU 进程；复用初版自建的 `gpu_smoke`，单卡及同进程八卡各运行 20 秒，外层 timeout 为 25 秒。每卡显式分配 64 MiB，实际每卡进程显存最大 **116391936 字节（111 MiB）**，结束后均验证进程消失、显存释放。观测到单卡利用率峰值 20%，八卡测试中设备瞬时峰值 100%；这些是 GMI 的瞬时采样，不代表持续满负载或性能结果。

负载发生在连续历史采样期间。采样数、五分钟窗口填充／淘汰和监控资源统计见下方十分钟结果。

### 十分钟历史验收

后台采样连续运行 **600.000 秒**，取得 **600 个快照**，采集错误、过期快照及验收失败均为零。

| 项目 | 实际结果 |
| --- | --- |
| 最大观察采样间隔 | 1.204 秒 |
| 历史窗口 | 300 秒，观察到的最老桶年龄最大 299 秒 |
| 每卡有效秒桶 | 窗口填满后 295–299 个；不超过 300 个 |
| 初始桶淘汰 | 八张 GPU 均验证通过 |
| 监控进程 RSS | 16695296–18571264 字节 |
| 后半程 RSS 最大增长 | 241664 字节，低于 16 MiB 验收阈值 |
| Python 监控进程平均 CPU | 单核的 0.637%，不包含 GMI 子进程 |
| 清理 | 无遗留 GPU 测试进程，八卡显存已用与利用率均回到零 |

连续观察到每张卡的显存占用从零升至约 0.1355% 后回落，并记录到利用率变化。实际查询耗时与调度存在抖动，同秒记录会合并，故 300 秒窗口不必恰好包含 300 个有效桶。缺口未插值，数据未填零。

十分钟结果来自实际后台采样；UI 的响应与恢复来自前述独立真机伪终端检查，不把模拟时钟测试或短时 UI 检查称作十分钟 UI 稳定性测试。历史为当前会话内存数据，只展示峰值趋势，不提供长期保存或回放。
